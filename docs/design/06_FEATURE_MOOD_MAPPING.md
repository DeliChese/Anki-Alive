## 1. Purpose

This document defines the canonical mood and visual personality of each major Anki Alive feature.

Its purpose is to ensure that:

- features feel distinct,
- the product still feels unified,
- AI agents do not create separate visual universes,
- feature identity is expressed through more than color,
- motion and copy tone remain semantically coherent.

A feature should be recognizable even in grayscale.

Color is not enough.

---

# 2. Feature Identity North Star

Every feature belongs to the same world:

> **A living observatory of memory.**

Each feature represents a different way of reading memory.

```text
Expedition
→ movement through memory

Oracle
→ uncertainty and prediction

Rescue
→ fragility and recovery

Nemesis
→ persistent resistance

Fragments
→ incomplete discovery

Relics
→ preserved long-term identity

Memory World
→ accumulated memory landscape
```

These are not separate mini-games.

They are different instruments observing one memory system.

---

# 3. Shared World Rules

All features must share:

- typography system,
- spacing scale,
- surface hierarchy,
- semantic color logic,
- motion tiers,
- focus behavior,
- accessibility rules,
- restraint philosophy.

Feature identity may vary through:

- geometry,
- accent family,
- symbol,
- material nuance,
- motion verb,
- atmosphere,
- copy tone.

---

# 4. Feature Differentiation Stack

Feature identity should be built in this order:

```text
1. Semantic purpose
2. Geometry
3. Motion verbs
4. Material nuance
5. Symbol language
6. Accent color
7. Copy tone
8. Optional atmosphere
```

Do not start with color and stop there.

# 25. Cross-Feature Event Collision Rule

If multiple features trigger at one review boundary:

1. EventOrchestrator chooses prominence.
2. One feature may receive MAJOR treatment.
3. Other events downgrade to:
   - MINOR,
   - AMBIENT,
   - DEFERRED.
4. Visual identities must not compete simultaneously.

Never show:

```text
Oracle reveal
+
Rescue animation
+
Nemesis animation
+
Fragment animation
```

at the same moment.

# 31. AI Feature Drift Detection

Reject or revise a feature if:

- identity depends only on color,
- it uses generic cards with a new accent,
- motion verbs overlap completely with another feature,
- geometry contradicts its canonical metaphor,
- copy tone feels like a different product,
- it introduces unrelated material language,
- spectacle exceeds prominence ceiling,
- it becomes more visually important than recall.

---

# 32. Cross-Feature Cohesion Checklist

Before accepting a new feature screen, verify:

1. Is the feature recognizable without color?
2. Is it recognizable without motion?
3. Does it use canonical geometry?
4. Does it use canonical motion verbs?
5. Does it use shared typography?
6. Does it use shared surfaces?
7. Is its accent local and restrained?
8. Does it feel distinct from neighboring features?
9. Does it still feel like Anki Alive?
10. Does Focus Mode preserve identity?
11. Does Reduced Motion preserve meaning?
12. Would it still feel coherent beside every other feature?
