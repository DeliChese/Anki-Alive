# Anki Alive — Visual Constitution

Status: CANONICAL
Applies to: all UI, visual assets, motion, feature presentation, generated art, and AI-authored frontend work
Art Direction: Arcane Memory Interface
Core Aesthetic: Dark Arcane + Modern Minimal

---

## 1. Purpose

This document defines the visual constitution of Anki Alive.

It exists to prevent stylistic drift across:

- features,
- phases,
- contributors,
- coding agents,
- design agents,
- image-generation systems,
- future UI frameworks,
- future model changes.

This document is stronger than individual aesthetic preferences.

A contributor or AI may improve execution quality, but must not silently change the visual identity of the product.

When a visual decision is ambiguous, prefer the option that better preserves:

1. recall clarity,
2. calm hierarchy,
3. restrained atmosphere,
4. meaningful symbolism,
5. long-term usability.

---

# 2. Visual North Star

Anki Alive should feel like:

> **A living observatory of memory.**

The interface combines:

- intelligent instruments,
- quiet ritual,
- preserved history,
- cartographic discovery,
- mineral artifacts,
- luminous signals,
- modern information design.

The visual experience should suggest that the learner is observing and shaping a living memory system.

It must not resemble a decorative fantasy game pasted on top of Anki.

---

# 3. Core Art Direction

## 3.1 Canonical Name

**Arcane Memory Interface**

## 3.2 Core Formula

```text
Dark Arcane
+
Modern Minimal
+
Precise Instrumentation
+
Quiet Atmosphere
+
Meaningful Motion
```

No individual part may dominate the others.

Too much arcane styling becomes fantasy decoration.

Too much minimalism becomes generic productivity software.

Too much instrumentation becomes a dense sci-fi HUD.

Too much atmosphere becomes visual noise.

The goal is controlled synthesis.

# 7. Hierarchy of Meaning

Visual prominence must follow semantic importance.

The default hierarchy is:

```text
Recall content
↓
Primary action / active learning state
↓
Current Expedition progress
↓
Important feature signal
↓
Secondary metadata
↓
Atmosphere
↓
Decoration
```

Decoration must never outrank information.

Atmosphere must never outrank recall.

Motion must never outrank interaction.

---

# 8. Recall Dominance Rule

During active recall:

> **The card is the visual authority.**

Supporting UI must remain subordinate.

Allowed:

- compact Expedition progress,
- tiny signal markers,
- subtle status changes,
- Focus Mode indicators,
- very small ambient feedback.

Forbidden:

- large animated overlays,
- moving particles near card content,
- pulsing attention traps,
- glowing borders competing with the answer area,
- cinematic reveals,
- animated text unrelated to recall,
- persistent motion.

The user should never need to visually fight the add-on in order to answer.

---

# 9. Quiet by Default

The resting state of Anki Alive should be calm.

Most screens should not contain continuously animated elements.

A visually rich product does not require constant motion.

The default state should feel:

- composed,
- stable,
- intentional,
- readable.

Meaningful animation gains power because most of the interface is quiet.

---

# 10. Restraint Principle

When choosing between:

```text
more glow
vs
less glow
```

prefer less glow.

When choosing between:

```text
more motion
vs
less motion
```

prefer less motion.

When choosing between:

```text
more ornament
vs
clearer hierarchy
```

prefer clearer hierarchy.

When choosing between:

```text
more effects
vs
one strong effect
```

prefer one strong effect.

Restraint is part of the brand.

---

# 11. One-Focal-Effect Rule

A standard screen should have at most:

> **one dominant atmospheric or expressive visual effect.**

Examples:

Good:

- one subtle luminous Expedition path,
- one Oracle halo,
- one Relic artifact hero,
- one atmospheric Memory World background.

Bad:

```text
aurora
+ particles
+ animated gradient
+ glow border
+ shimmer
+ rotating rings
+ floating icons
+ parallax
```

all on the same surface.

The interface must never become an effect showcase.

---

# 12. Surface Philosophy

Surfaces should feel:

- matte,
- dense,
- refined,
- layered,
- subtly luminous,
- visually stable.

Preferred material cues:

- charcoal,
- obsidian,
- deep ink,
- dark mineral,
- translucent instrument glass used sparingly,
- soft luminous edge,
- subtle internal light,
- restrained grain.

Avoid:

- excessive glassmorphism,
- heavy frosted blur,
- glossy plastic,
- chrome-heavy surfaces,
- exaggerated drop shadows,
- rainbow reflection,
- fake metallic ornament everywhere.

---

# 13. Glow Constitution

Glow is a semantic resource.

Glow may indicate:

- active state,
- resonance,
- mystery,
- stability,
- discovery,
- milestone,
- rare significance.

Glow must not become ambient wallpaper.

Rules:

- default surfaces should not glow,
- active surfaces may glow subtly,
- major events may briefly intensify glow,
- glow should decay after emphasis,
- text glow should be extremely rare,
- large bloom effects are prohibited during recall.

If everything glows, nothing matters.

---

# 14. Color Philosophy

The product is primarily low-chroma.

The visual field should be dominated by:

- deep blue-black,
- charcoal-violet,
- dark slate,
- muted cool neutrals.

Bright color is reserved for meaning.

Feature accents should remain distinct but related.

Preferred direction:

```text
Expedition
→ muted amber / path-light / antique gold

Oracle
→ pale cyan / moonlight / luminous blue

Rescue
→ teal / restorative sea-glow

Nemesis
→ dark crimson / bruised violet / pressure red

Fragment
→ crystalline lavender / spectral prism

Relic
→ ancient gold / mineral ivory / auric light

Memory World
→ atmospheric blue-green / constellation slate
```

Avoid:

- rainbow interfaces,
- saturated color everywhere,
- neon cyan + neon magenta cyberpunk defaults,
- unrelated gradients,
- red used merely for drama,
- green used as the only success signal.

---

# 15. Typography Constitution

Typography must feel:

- modern,
- clear,
- intelligent,
- restrained.

It must not feel:

- medieval,

- arcade,
- comic,

- composition,
- spacing,
- symbolism,

Not from unreadable fonts.

Display typography may carry more character.

Body typography must prioritize reading comfort.

# 18. Motion Constitution

Motion exists to communicate:

- state change,
- causality,
- progress,
- hierarchy,
- completion,
- discovery.

Motion must not exist merely because animation is possible.

All motion must eventually map to an approved motion primitive or effect ID.

Future motion catalog entries should use names such as:

```text
AA-FadeRise-01
AA-HoverLift-01
AA-GlowEdge-01
AA-OracleReveal-01
AA-Milestone-01
AA-NumberFlow-01
```

AI agents must not invent uncontrolled motion styles when an approved primitive exists.

---

# 19. Motion Intensity Tiers

## M0 — Quiet
Use during:
- reviewer question state,
- Focus Mode,
- high-attention learning moments.

Allowed:
- opacity transition,
- very small transform,
- subtle state change,
- tiny progress interpolation.

## M1 — Functional
Use for:
- navigation,
- panels,
- tabs,
- list transitions,
- dashboard interactions.

Allowed:
- panel entrance,
- hover lift,
- progress interpolation,
- compact stagger,
- layout transition.

## M2 — Expressive
Use for:
- milestones,
- event reveals,
- checkpoint completion,
- meaningful discoveries.

Allowed:
- controlled glow,
- staged reveal,
- border illumination,
- icon resolution,
- restrained particles if explicitly approved.

## M3 — Cinematic
Use only for:
- rare major milestones,
- Oracle centerpiece events,
- Relic formation,
- major Memory World moments.

M3 must be explicitly allowed by the feature specification.
M3 is never the default.

---

# 20. Reviewer Motion Ceiling

Reviewer question state:

```text
Maximum motion tier: M0
```

Reviewer answer state:

```text
Maximum motion tier: M1
```

Post-grade boundary:

```text
M2 allowed only for one orchestrated meaningful event
```

M3 should generally be deferred outside active review.

---

# 21. Focus Mode Constitution

Focus Mode is not an inferior visual mode.

It is a quieter expression of the same design language.

Focus Mode must:

- preserve hierarchy,
- preserve beauty,
- preserve useful progress,
- reduce animation,
- suppress nonessential reveals,
- reduce ambient effects,
- avoid visual punishment.

Focus Mode should generally reduce presentation to:

```text
M0
+
essential M1
```

M2 and M3 should normally be suppressed or deferred.

---

# 22. Reduced Motion Constitution

Every significant animated effect must define a reduced-motion behavior.

Allowed fallbacks:

- opacity-only transition,
- instant state change,
- static highlight,
- short dissolve,
- non-moving luminance change.

Reduced motion must not remove important meaning.

No feature may require motion in order to understand state.

---

# 23. Accessibility Constitution

Visual beauty never overrides usability.

All UI must consider:

- readable contrast,
- keyboard focus,
- scalable text,
- non-color status communication,
- reduced motion,
- understandable hierarchy,
- adequate hit targets,
- predictable dismissal.

Decorative effects must not obscure text.

Feature symbolism must have textual or structural equivalents where necessary.

---

# 24. Generated Art Constitution

Generated imagery may support:

- atmosphere,
- feature identity,
- background texture,
- hero visuals,
- Relic identity,
- Memory World mood,
- Fragment discovery.

Generated art must not replace:

- buttons,
- labels,
- progress indicators,
- core navigation,
- reviewer controls,
- essential state communication.

Generated art is supporting visual language, not interface logic.

Symptoms:
- parchment,

## 25.4 Cyberpunk Drift
Symptoms:
- neon cyan/magenta,
- scanlines,

- dense HUD grids,

## 25.5 Mobile Game Reward Design
Symptoms:
- bouncing rewards,
- confetti spam,
- rarity bursts,

## 25.6 Dead Minimalism
Symptoms:
- monochrome SaaS cards,
- no atmosphere,
- no symbolic identity,
- no feature differentiation,
- generic utility UI.

Anki Alive must remain minimal without becoming sterile.

# 26. Anti-Decoration Rule

Before adding a decorative element, ask:

> What meaning does this support?

Valid answers include:

- feature identity,
- state,
- importance,
- progress,
- history,
- hierarchy,
- atmosphere.

Invalid answer:

> It looked empty.

Empty space is allowed.

Breathing room is part of the design.

---

# 27. Visual Density Rule

Do not fill every available region.

Prefer:

- whitespace,
- breathing room,
- intentional grouping,
- progressive disclosure.

Avoid:

- dashboard density,
- micro-label overload,
- decorative widgets,
- excessive side panels.

Desktop space is not an obligation to show more information.

---

# 28. Animation Timing Philosophy

Motion should feel deliberate, not playful.

Preferred ranges:

```text
120 ms
micro interaction

180–220 ms
functional transition

280–380 ms
meaningful reveal

450–650 ms
rare major transition
```

Avoid:

- long idle loops,
- bounce-heavy easing,
- exaggerated spring overshoot,
- forced animation delays.

No animation should make the learner wait before continuing review.

---

# 29. Event Prominence Constitution

Presentation prominence:

```text
AMBIENT
MINOR
MAJOR
SESSION_CLOSURE
```

Rules:

- AMBIENT may coexist with normal UI.
- MINOR should remain compact.
- MAJOR must be orchestrated.
- At most one MAJOR event may surface per review boundary.
- SESSION_CLOSURE may receive stronger visual treatment because recall has ended.

---

# 30. Closure Visual Rule

Completion should feel final.

After Expedition completion:

- visually acknowledge the finish,
- stabilize the interface,
- allow the user to stop,
- do not immediately produce another mandatory objective.

Celebration should resolve into calm.

The visual system must reinforce closure, not endless continuation.

---

# 31. Long-Term Aging Rule

Anki Alive should become more meaningful over months and years.

Visual systems should support:

- accumulated history,
- persistent artifacts,
- evolving map state,
- meaningful wear / fracture / restoration,
- personal chronology.

Avoid visual systems that rely entirely on novelty.

The product should gain depth with age.

---

# 32. Implementation Rule for AI Agents

Before implementing UI, an AI agent must identify:

```text
1. Feature
2. Semantic state
3. Required prominence
4. Allowed motion tier
5. Approved visual metaphor
6. Approved surface style
7. Approved effect IDs
8. Focus Mode behavior
9. Reduced-motion fallback
10. Performance implications
```

If any of these are unknown, the agent should consult canonical design documents before inventing new behavior.

---

# 33. AI Permission Boundary

AI agents MAY:

- improve spacing,
- improve hierarchy,
- improve consistency,
- improve accessibility,
- use approved motion primitives,
- refine approved surfaces,
- propose new effect primitives for review.

AI agents MUST NOT silently:

- introduce new visual themes,
- increase motion tier,
- invent feature-specific design systems,
- add new color families,
- add major dependencies for visual novelty,
- introduce casino-like presentation,
- redesign reviewer hierarchy,
- replace canonical symbols,
- invent uncontrolled animation systems.

---

# 34. New Effect Admission Rule

A new visual or motion effect should only enter the system if:

1. existing primitives cannot express the meaning,
2. the effect has a clear semantic purpose,
3. it fits Arcane Memory Interface,
4. it has a reduced-motion fallback,
5. it respects Focus Mode,
6. it has acceptable performance,
7. it does not distract from recall,
8. it can be reused or is important enough to justify uniqueness.

New effects should be documented before widespread use.

---

# 35. Visual Review Questions

Before a UI is considered complete, ask:

1. Is the learner's primary task visually obvious?
2. Is the screen calm when nothing important is happening?
3. Does the feature have recognizable visual identity?
4. Does it still belong to the same product as other features?
5. Is glow rare and meaningful?
6. Is motion semantic rather than decorative?
7. Is the interface readable without animation?
8. Does Focus Mode remain elegant?
9. Does reduced motion preserve meaning?
10. Is there any visual element competing with recall?
11. Does this look like a premium memory instrument rather than a game skin?
12. Would this still feel tasteful after seeing it every day for one year?

If several answers are unfavorable, the design is not finished.

---

- too many badges,

- glowing text,
- unnecessary charts,
- dashboard clutter,
- random particles,

- cyberpunk styling,
- multiple competing accent colors,
- novelty typography,
- reward spam,
- constant movement.

# 37. Canonical Conflict Resolution

When visual documents appear to conflict, use this priority:

```text
Product Principles
↓
Visual Constitution
↓
Design System
↓
Feature Phase Spec
↓
Effects Catalog
↓
Component Canon
↓
Implementation
```

If a lower-level document contradicts a higher-level rule, the lower-level design should change.

---

# 38. Final Visual Principle

When uncertain, return to this question:

> **Does this make memory feel more meaningful, or does it merely make the interface more decorative?**

Anki Alive should always choose meaning.

And when two visually valid solutions exist:

> **Choose the quieter one unless the event has earned spectacle.**
